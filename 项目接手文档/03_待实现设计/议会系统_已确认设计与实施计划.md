**状态：2026-11-07已实装。** 主机制与界面已接入，29项静态、31项后台和3项真实读档检查通过。实际运行接口以[维护说明](../../tools/parliament/README.md)为准，验证范围见[实装记录](../../docs/parliament/20261107-implementation/README.md)。开局正式输入位于 `tools/parliament/data/opening_countries.json`；国家历史仅追加选举日历，人物、意识形态与地图保留。

## 一 席位与选举

- 固定500个整数席位，每点一席；使用数学点位、确定性脚本和GUI，不使用生图模型。13排是既有示意布局参数，不是引擎限制；保存源参数和生成程序。
- 权重为“当前民意支持率 × (1 + 该主意识形态议员席位系数)”。例如先锋社会主义系数+10%，只把其分席权重乘1.10，不修改真实民意。
- 按最大余数法归一化分500席：先取整数下限，再按余数补足。余数相同先比较支持率，仍相同抽签；多人、多席平票须整组处理。抽签结果存档，重开面板和读档不重抽。
- 当届席位固定至下次选举；开局先初始化一届，不每日随民意重分席。
- 默认从2060开局或国家释放日期起，每两年选举；日期计算沿用原版选举日历，不用固定730天代替两年。制作者可逐国设置x年或无选举。
- 选举同盟和执政联盟只能由剧情组建/调整，玩家不能手动建立；保留剧情API，不新增手动组建按钮。
- 单党或选举同盟按总席位争胜，无绝对过半要求。胜选同盟成为执政联盟，落败后仍保留选举同盟身份。
- 第一名同席位则延期半年重选，直至有胜者；延期期间现任继续执政。胜负平票不使用分席抽签代替。
- 换届保留全部已记录态度调整、当前议案、阶段和完成比例。依新席位、现任执政党及联盟重算派生支持率，继续执行阶段门槛。

工程边界：不按文件顺序打破平票；零总权重须走明确配置错误出口，不能发布不足500席的新届。原始支持率与特殊修正同时影响平票时的排序口径，须在实现说明中明确，不能隐式改变。

## 二 党派态度与法案支持

序位明确为：先锋社、广泛社、社民、自由、保守、威权、独裁、法西斯、原教旨。内部key依次为communism、socialism、social_democracy、liberalism、conservatism、authoritarianism、dictatorship、fascism、fundamentalism。不要借用旧代码中保守与自由的排列。

    基础态度 = -10% × 双方序位距离
    执政党对自身态度 = 恒定100%
    其他党对执政党态度 = clamp(基础态度 + 各额外来源 + 联盟成员加100%, -100%, 100%)
    该党对当前法案的支持 = clamp(对执政党态度 + 对该法案的态度, -100%, 100%)

对具体法案的态度默认0，按党派及活动法案分别保存。谈判只调整此项，不改民意、固定席位或对执政党的基础态度。联盟加100%是独立来源，刷新时重算，不反复累加。

    S = 50% + 政体党派反对权 × Σ(该党席位/500 × 该党对法案的支持)

50%基础不乘反对权。反对权100%时S范围-50%至150%；50%时0%至100%；0%时恒为50%。不能把S限制到0—100，也不改成普通赞成票占比。

## 三 党派实际加成

    实际党派修正 = 基础修正 × 当届席位占比 × 对执政党态度 × 政体党派加成比例

不额外乘一次当前民意。用户确认例：基础建设速度100%、席位40%、态度50%、政体比例75%，实际为+15%。态度保留符号，负面态度使修正反向。

| 主意识形态 | 基础修正 |
|---|---|
| 先锋社会主义 | 建设速度+100% |
| 广泛社会主义 | 工厂产出+100% |
| 社会民主主义 | 每月人口+100% |
| 自由主义 | 生活消费品人口系数-50% |
| 保守主义 | 稳定度+50% |
| 威权主义 | 每日政治点数获取+100% |
| 独裁制 | 议案审议速度-50% |
| 法西斯主义 | 战争支持度+50% |
| 原教旨主义 | 适役人口系数+100% |

## 四 审议速度与三阶段

    高支持率额外速度 H = min(100%, max(0%, 2 × (S - 100%)))
    有效速度倍率 = (1 + 普通审议速度修正) × (1 + H)
    当前完整等效用时 = 政体基础审议时间 / 有效速度倍率
    剩余时间 = (1 - 已完成比例) × 当前完整等效用时

用户确认普通+10%、高支持率额外+20%时为1.10×1.20=1.32，不是1.30。100%上限仅针对H。速度变化保留完成比例；已完成50%、新完整用时30天，则还需15天。三个阶段各占标准化总进度的1/3；中途变速不追溯修改已过去的日历时间。

| 阶段 | 期间与结束判定 |
|---|---|
| 宣读 | 可暂时低于0%；结束时须S>0% |
| 辩论 | S<0%立即失败；结束时S>=50%进入审议 |
| 审议 | S<50%立即失败；维持门槛至完成即通过 |

恰好50%可进入审议并继续。基础时间为“立刻”的政体使用即时结算路径，不让零时间参与除法。极端普通速度使倍率不为正时须显式处理，不能出现负剩余时间。

## 六 双特质与任命

- 每位可任命人物需要成员特质、首席特质两套定义。普通六槽使用成员特质；总理、副总理使用首席特质。换岗先撤旧岗位效果再加新效果，不能叠加两套。
- 总理、副总理与六槽使用同一候选面板和任命流程；两首席候选限定本届胜选方。普通六槽仅显示执政联盟候选，沿用现有内阁名额分配方法。
- 每次胜选有一次免费组阁，覆盖总理、副总理各一人。两个岗位各首次任命免费；重复更换已用掉免费机会的岗位支付费用。开关面板不重置，存档保留消耗情况。不能解释成两职只免费任命一人。
- 六个普通槽仍花政治点；一人只能占总理、副总理或六槽之一。保留现有真实顾问效果、人物和头像。
- 新人物具体首席特质数值后续提供；缺定义先留接口，不伪造加成。非免费任命费用作为可配置平衡值。

## 七 单议程 谈判与封禁

- 同时只能有一项活动议程。政治改革、特殊议案、封禁/解封走统一三阶段；有议程时禁止提交任何其他需审议的更改，不暗中排队。
- 谈判在任一活动阶段且对应党有议席时可用，否则灰化。事件先做贿赂、政治让步等临时选项；用户允许先临时设计，后续完善。
- 禁止封禁现任执政党及任何执政联盟成员。提交和执行时复核保护条件，防止换届或剧情调整后执行已失效封禁。
- 点击封禁只提交议程；通过后生效。有议席则立即重新选举，无议席不重选。被禁党不参加选举，不能删除人物、国家定义或真实民意。
- 被禁党按钮变为解封，解封也须审议；通过后参加下一届选举，不立即恢复旧席位。
- 换届保留谈判态度与法案进度；议案结束时按实例清理临时记录，不跨法案串用。
