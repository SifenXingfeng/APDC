# 常见操作复用手册

下列步骤是复用入口，不表示现在已经运行过一次。本次接手整理不生成运行文件。

2026-11-10起统一使用 [tools/compile.py](../../tools/compile.py) 选择编译任务，`--list`列出入口。议会自定义素材和原始Word已纳入 `tools/assets/parliament/`，不再依赖桌面；其他历史任务的桌面来源和副作用仍须按下文核查，不因统一入口而自动重导入。

## 先判断程序类型

| 类型 | 代表 | 使用原则 |
|---|---|---|
| 日常来源驱动生成 | 经济build_backend、cold_war/build.py | 查依赖/输入与输出保护后，在本轮备份基础上重建受影响部分 |
| 依赖桌面源图/Word | 经济build_data、build_ui | 先确认文件存在、内容结构及用户最后修正，防止把旧图/段落编号重导入 |
| 稳定ID/存档协议 | equipment_ids、cold_war law id | 不重排、不复用退役编号，写迁移，不清空库存/现任席位 |
| 日期专项变更器 | finish_20261027、upgrade_1194、D盘country_sync | 当案例参考；旧输入/HEAD/备份可能覆盖新数据，不得盲跑 |
| 只读静态审计 | UI/数字检查、engine_callbacks、部分audit | 先读main，看是否顺带生成QA/改文件；名字叫audit也不能默认只读 |
| 后台验证准备/启动 | runtime.py、qa.py、launch_silent | 很多旧默认D路径需改到本轮共用C目录；不要一条build顺带开游戏 |

## 一、加一个冷战行动

按[原生内容接口](../../tools/native_content.md)复制行动模板到独立脚本，填写ID、目标、轴、受益国、日增量、费用、条件和生命周期效果；添加正常文本与同步键，在事件/国策/决议中一行调用本内容的解锁包装。政治/经济/军事、对外/本国/接受影响共用同一API。不改JSON、中央GUI分支或重建地图；可选 `native-content-check` 只读检查。

## 二、加一个合作组织/组织规则

新组织仍复用模板与容器API，明确名称、图标、成员和主席。新规则复制[原生规则模板](../../tools/templates/native_organization_rule.txt.example)，在锚点调用自己的登记包装；成员可用自己的命名提案包装正常排队投票。填写锚点/成员的实施与撤销回调，名字和选项显示从定义自动接入列表、队列和投票。重复登记保留选项与锁；成员进退、换规则、解散使用共享清理链。无须编译。

新增候选同样按[原生候选模板](../../tools/templates/native_candidate.txt.example)填写定义，剧情一行登记；不编辑 `candidates.json`，不重建头像或500席布局。

## 三、改经济法案或发展度数值

1. 对照 [docs/economy/design_data.json](<../../docs/economy/design_data.json>)及参数附录；如确需重读Word，检查build_data固定段落切片没有漂移。
2. 修改正式来源，生成数据/法案/本地化；核对80档modifier块与用户数值、色号/好坏语义。
3. 需要后端时调用普通 `build_backend.py`，不带迁移；只改来源提示时改 `direct_sources.py/presentation.py`和UI生成。
4. 原生人口系数固定展示交给 `build_law_stat_display.py`；不写回原生消费品期望值。
5. 同时检查实际可用民工、当前分配、加减可选状态，不能只验证聚合修正为0。

## 四、加装备/科技并接私营生产

原生装备/模块/科技先合法；追加稳定equipment ID，不填回旧退役ID。完整预设需满足已解锁模块，不选国家专属/专项模块作通用默认。生成目录、库存数组、购买映射；保留原有科技完成回调及limit，在其完成时设置dirty。验证旧库存、旧代停产仍可买、更新目录不清进度、价格按完整成本×200、计划经济转库存免费。

## 五、改人物大头像

1. 确认用户范围是党首/国家领袖大头像，还是明确还包括内阁/顾问；默认不扩范围。
2. 搜人物名字本地化→角色token→现有各角色与portrait；同名仅以明确身份合并。
3. 新图转换专用DDS与sprite，只改指定 `civilian.large`；共用通用图不要原位替换影响其他人。
4. 像素回读验证；原角色、traits、招募、党派、小头像与其他人物哈希保持。
5. 无新图保留旧图；新建无图人物才用默认。显示名中分隔符用“·”，文件路径/token不跟着全局替换。

## 六、同步国家/意识形态文档

解析到结构化stage→列差异/冲突→落实有授权部分→保护原定人物/党派/排除字段→补token/GFX/loc→重复键/引用检查。默认/空白规则和16项已留冲突见专题。

现有D盘导入器绑定10月28日原始备份，需要先改为**本轮现场**来源，避免重放旧值。批量补Word若有授权，保留原有XML块/三表结构，只追加缺失tag；渲染后验证分页和表格，不把封面旧数当条目数。

## 七、地图收尾与冷战更新

执行根AGENTS十五步。固定来源精确分配，实时拥有关系、州文件索引、城市与模型位置、补给铁路同步。只归属/核心改动不重算人口和地形；改地块轮廓才更新冷战地理。

`refresh_geography.py`使用stage与当前备份内旧geometry，保护非地理GUI。旧finish/railway脚本不能再次按固定清单执行。新检查点以本次最终状态保存，不恢复GF国家史。

## 八、确定性素材导出

TGA/DDS→PNG直接解码、保持原尺寸/Alpha；回读比较像素。导出大旗不要拿medium/small，不混COG/RCG/cosmetic。模型包按引用闭包选文件，不混入整个项目与QA。

源美术替换后检查**实际加载的**纹理、sprite/帧数、frame状态和GUI尺寸。三帧/两帧素材不可擅自按错误切片压缩。修改生成器同步来源，避免下次build覆盖回旧版。

## 九、下一轮原版升级

建立新的原版文件指纹，与项目有效覆盖和旧基线三方对照；补接口，保留项目平衡/布局。查图集最终覆盖，不只查本体存在。运行前静态解析及入口检查；若涉及初始数据库开新局，不承诺旧存档自动获得新初始值。

## 十、扩展新系统通用模板

特殊法案已支持[原生内容制作](../../tools/parliament/special_bills.md)：复制独立脚本模板、填显隐/可用/费用和三个回调、维护本地化与同步键，再在剧情中一行解锁。新增法案不重编议会，不编辑中央分发表；旧JSON只作兼容。

依次落实：数据定义/稳定ID→有scope说明的API→生命周期（启用、停止、移除、国亡、重载、版本迁移）→GUI及dirty更新→本地化/素材→静态与真实功能验收→当前状态文档。

将来议会/君主制先做最小原型与数据边界，再批量国家扩展。不要用目前不存在的建议API写正式剧情；接口命名和目录必须先真正建立。
