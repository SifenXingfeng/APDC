# 2026-11-07 议会系统实装记录

后续界面以[九项UI修正记录](../20261107-ui-corrections/README.md)为准，原生输入配置、经济选择器和入口对位已进一步修正。

议会主流程已接入APDC主项目。500席选举、九类党派态度与加成、九种政体、六组43档通用法案、单议程三阶段、谈判、封禁/解封、八岗位任命与经济体制新效果均有运行脚本。原政治页六槽区域改为常驻议席与讲台入口，总理和副总理保留；旧独立内阁选择面板已移入议会。

## 规则落地

- 最大余数分配500个整数席位。席位系数只影响分席权重；余数同值先比未加权民意，再抽签。席位和点阵颜色保存，不因打开面板重新分配。
- 原生日历默认两年，支持逐国周期及无选举。第一名同席保留现任，六个月后再选；剧情维护选举同盟与执政联盟，没有手动组建入口。胜选同盟内部以席位最多的合法党执政，同席先原始民意后抽签。
- 对政府态度与单项法案态度分开。执政党固定100%，联盟其他成员额外加100%后封顶。法案贡献按党席位、夹取后的法案支持与政体反对权计算，不对总支持率再次封顶。
- 党派加成按基础效果×席位比例×对政府态度×政体加成比例，不额外乘民意。
- 审议累计等效工作量，速度变化只改变剩余工作所需时间。普通速度与超100%支持率产生的加速相乘；三个阶段各占三分之一。50%可以进入审议，审议中低于50%失败。
- 只有一项活动议程。谈判仅在有议程且该党有席位时可用；谈判修改该项法案态度。封禁保护执政党与联盟成员，通过后有旧席位才立即重选；解封等待下届选举。
- 六个普通岗位使用成员效果，总理/副总理使用首席效果，一人一岗。胜选后总理、副总理各有一次免费初任额度，更换收费；普通六槽沿用原名额算法。
- 经济入口与经济体制法案共用原有setter；顶部政体与政治体制法案共用状态。分散计划保留私营产业，仅中央计划国有化并禁止私营扩张。采购系数作用于真实报价与支付，−100%为零价，原装备库存仍正常消耗。
- 按用户最后更正，感染者“每月人力”与遗迹“每周人力”都按每月人口增长率实现，后者作为原文笔误修正。没有按人力池执行周期增减。

## 可维护来源与临时数值

维护说明、实际可用的原生剧情API和特殊议案示例见 [tools/parliament/README.md](../../../tools/parliament/README.md)。`tools/parliament/data/` 保存法案、政体、344个国家开局配置、231个持久候选ID、态度来源与特殊议案目录。新增候选ID不得重新编号；现有真实人物和头像保留，德国旧占位成员继续保留。

普通任命150政治点沿用旧值；首席更换300政治点、通用法案提案150政治点暂作初始平衡。谈判先放置100K贿赂获得该法案态度+20%、50政治点让步获得+15%和退出选项。临时值均集中维护，后续可改。

人物已有成员效果已保留；未提供的成员/首席具体特质保持空定义，待逐人填写。特殊议案默认空，支持逐国目录、可见/可用条件、费用、提交/通过/失败回调。人形科技与遗迹专项计划仅留对应科研接口；企业收购、掠夺仅留权限及价格接口，未制作实际企业交易。君主立宪制的独立元首展示分离继续是另一项未实装设计。
