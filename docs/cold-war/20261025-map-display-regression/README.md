# 冷战地图初次显示回归修复（2026-10-25）

## 故障与责任

缓存优化把“地图数据已计算”和“界面已应用这些数据”混为一谈。加载时缓存已有效，但父面板隐藏期间 GUI 的 dirty 版本已被消费；正常初次打开直接复用同一版本，导致字面默认第一帧红色以及默认可见的全部边界没有被覆盖。

最小复现只执行真实入口回调，不预先改变领土或控制比例：日志显示打开前后 `ui=1`、法国缓存 `FRA=3` 正确，画面仍完整复现用户的全图红色。上一次验收先进行了领土与控制变动，触发刷新后才截图，遗漏了真实首次打开路径；此前的全面视觉结论不成立。

## 修复

有效缓存继续复用。新增独立的画面绑定步骤，在打开、重新打开、从详情返回及加载时推进 GUI 更新版本；仅缓存失效时重新计算地图。用独立的缓存构建计数检查计算是否重复，不再把 GUI 更新计数作为缓存构建次数。

未改动 `.gfx`、着色器、GUI 布局、美术素材或分辨率。用户选定的原生部件模式保持不变。

## 验证

后台普通 GER 2060 开局；在任何测试用领土/控制改动之前，分别执行入口、关闭、重开、实际法国地图入口与返回回调，保存五个原生画面。世界地图初次打开、重新打开、返回各 500,000 像素及法国详情 250,000 像素，与原正确原生对照全部一致。关闭画面人工检查面板完全隐藏。

五个场景中的缓存构建次数均为 1；画面更新版本在初次打开、重开、返回时分别为 3、4、5。随后才运行数据集成测试，87 项通过。3,129 个脚本解析通过，项目及未归类错误为 0，原有 705 条外部记录仍按既有来源归类。3,635 个保护文件哈希不变，州历史无变化。

未发送鼠标或键盘输入，回调执行和原生画面检查不描述为真实鼠标点击验证。测试游戏及两个辅助进程已关闭，Steam 运行标志已清理。无需清除用户存档；新代码需重启游戏加载。
