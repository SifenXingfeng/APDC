## 候选人的具体依赖

来源为 `tools/parliament/data/candidates.json`。`tools/parliament/cabinet.py::generate` 会逐人生成可见/可用条件、任命、旧idea移除、角色清退、配额统计、联盟变动处理以及姓名/头像/特质映射；`tools/parliament/ui.py` 还枚举可点击条件，`assets.py` 逐人处理头像。

实际运行入口包括 `common/scripted_effects/apdc_parliament_cabinet.txt` 的 `apdc_parl_refresh_candidates`、`apdc_parl_appoint_selected`，以及对应triggers、scripted_localisation和scripted_gui。

因此，仅在 `common/characters/` 增加人物不会自动进入候选列表；仅追加JSON也不会在游戏中生效。`build.py` 只在候选JSON不存在时调用 `import_candidates()`，正常重建也不等于自动扫描新增人物。不能把“游戏已有这个人物”当成“候选系统已经登记”。

## 全部冷战行动的具体依赖

当前28条行动分布为政治12、经济8、军事8，含对外22条、本国6条，全部经过同一条链：

- `tools/cold_war/build_laws.py`：逐条生成解锁包装。
- `tools/cold_war/build_ui.py`：逐条生成名称、说明及对应显示分支。
- `tools/cold_war/build_view.py`：逐条生成来源贡献缓存及饼图悬浮窗说明，当前还绑定来源中的施行国/目标国/受益国。

`common/scripted_effects/APDC_cold_war.txt` 已有原生 `apdc_cw_register_law`、锁定、移除、执行/停止和每日结算接口，所以后端不是完全不能追加。但只新增一个注册脚本，显示链不会自动补全，不能称为完整的独立行动定义。

现有通用结算实现是政治点数切换加三轴日变化；没有每条行动独立的执行、停止、每日自定义效果回调。直接改变份额、可干涉/已控制状态和国际地位的剧情接口已经原生可用，不需要重新生成世界地图。修复内容扩展不应重建地图、纹理或调整这些既定规则。

## 合作组织规则的具体遗漏

`APDC_register_cooperation_law_group_container` / `APDC_add_cooperation_law_group_to_container` 按数组扩容并登记规则组。追加第41组不需要复制GUI或重写投票算法，规则组总数并未固定为40。

但 `common/scripted_localisation/APDC_cooperation_organizations_scripted_localisation.txt` 中，列表、队列、当前投票的组名各有40个固定分支。选项名称/效果说明主要是第1、25组专用分支及通用占位。新增规则的名字不会仅凭新增本地化条目自动进入这三处显示。

`APDC_resolve_cooperation_law_vote_container` 在通过后只更新已选选项、修订号、成员的最后通过记录和效果旗标；没有调用规则专属的实施效果。扫描当前运行脚本，没有找到这些最后通过记录/效果旗标被其他玩法消费的实现。它们不能代替实际轮换主席、军事通行或其他正式规则效果。

另外，现有容器固定5类标签、每组1至4个选项。这是当前界面/数据结构边界，不是规则组总数上限。已有组重新注册会写回默认选项和可用状态，不能直接把“每次加载重新登记全部组”当成安全的旧存档迁移。

## 后续实现的验收标准

1. 新增内容可放独立原生文件，正常剧情调用其登记/解锁入口，不修改中央名单、GUI逐ID分支或运行生成器。
2. 名称、说明、头像/图标、条件、费用及实际效果都随内容定义接通；不能只证明多了一行列表。
3. 候选人保留八个职位、配额、真实人物去重、所属党派和成员/首席两套效果；冷战保留三轴及本国/对外全部行动、贡献提示；合作组织保留容器隔离、投票队列、成员同步和规则更替的效果清理。
4. 新定义不重排永久数字ID；新增文本token导致的枚举变化不能让旧存档串人物、行动或规则。按上一轮特殊法案的教训，身份与显示token必须分开处理。
5. 在不运行生成器的情况下追加测试内容并读取旧存档，验证显示数据、可用性、执行/撤销及已有记录保留，再报告迁移完成。不得凭这次静态审计声称运行验证通过。
