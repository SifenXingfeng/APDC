# 原版法案统计文本替换试验

> 后续按用户确认改用独立固定标签，详见 `../20261023-fixed-law-stat/README.md`。本试验保留为“直接读取国家修正无法得到不同候选值”的诊断记录。

本轮只在独立 QA 覆盖层修改 `POLITICS_IDEA_STAT_CONSUMER_GOODS`，没有把试验替换写进主项目。该 key 是原生法案 `stats` 文本的一段；煤炭使用另一段本地化，但两者共享同一个 `stats` 控件。

## 试验内容与结果

试用文本：

```text
 £consumer_goods_texticon£  [?modifier@APDC_eco_population_base|Y2]
```

引擎能够展开该文本，生成消费品图标标记和黄色两位小数，且没有改变原生消费品修正或工厂结算。

通过 `defined_text` 包装同一个 key，在 GER 国家作用域记录结果：

| 已生效法案 | 诊断标签：民用经济 | 诊断标签：总动员 |
|---|---:|---:|
| 民用经济 | 1.00 | 1.00 |
| 总动员 | 0.40 | 0.40 |
| 恢复民用经济 | 1.00 | 1.00 |

这里的“诊断标签”只是日志标签，并非伪造出的原生候选法案作用域。试验验证的是本地化表达式读取**国家当前聚合修正**，没有验证实际原生列表逐行绑定。不能把这份日志描述成已经打开原生列表、分别读取五个条目，更不能据此宣称引擎永远不支持逐行替换。

因此，这个直接读取国家修正的原型尚未实现需求：同一个国家的候选民用经济、总动员等条目应当同时显示不同的固定系数，而不是随当前法案一起改变。本轮未找到将原生候选法案标识传入该自定义文本的可靠接口，未将半成品合入主项目。
