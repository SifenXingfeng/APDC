# 民工归零与面板回归修复

> 后续按用户确认改用逐法案固定显示特质，保留原生图标和结算，详见 `../20261023-fixed-law-stat/README.md`。本文中的“原生系数显示未完成”记录的是该次恢复后的状态。

## 已确认的原因

16:07 后为显示人口消费品系数，错误地把 1.00、0.85 等数值重新放入原生 `consumer_goods_expected_value`：最初放在展示特质的隐藏修正中，之后又尝试放到经济法案自身。该字段仍参与原版工厂占用。检查聚合修正值不能证明实际没有占用；此前 27 项测试只执行回调、没有验证开局分配上限和按钮启用条件，漏掉了这个回归。

独立目录、相同主项目及 43 个 DLC 的对照结果：

- 当前错误配置：GER 总民工 30、已分配 0、可用 0。
- 仅换回 16:07 前的 `_economic.txt` 和分配动态修正：总民工 33、已分配 5、可用 28。
- 只换回分配动态修正、保留法案上的原生人口系数：仍为总民工 30、已分配 0、可用 0。聚合原生期望修正虽为 0，也没有恢复工厂。因此不能继续以聚合值为零判断抵消成功。

证据分别保存在 `runtime/factory-current`、`runtime/factory-old-data` 和 `runtime/factory-old-allocation-only`。第一份诊断中额外的 `remove_dynamic_modifier` 写法有误，不采用其移除阶段作为结论；第二份首次快照在任何诊断变更前记录。先前 16:57 的测试期间写入了经济后端，出现热重载后的大量无效 idea，整份结果不作为最终验收。

## 最终处理

- 原生经济法案和整个经济后端恢复为 16:07 前正常版本的原始字节，人口需求继续读取自定义 `APDC_eco_population_base`，系数保持 1、0.85、0.70、0.55、0.40。
- 分配动态修正继续隐藏，保留原有 `civilian_factory_use` 和 `consumer_goods_expected_value = -1`。没有改用工厂总数冒充可支配数量，也没有绕过按钮禁用条件。
- 删除有问题的展示特质和额外特质名称，生成器同步修正，避免再次生成影响原生占用的参数。
- 三个发展度按原先法案的方式使用 `allowed=no`、`available=no`、`cancel_if_invalid=no`、费用 -1。
- 主面板控件放回可拖动根窗口，背景使用被动图像；侧栏、贸易和采购 hook 缩为 1×1。删除引擎不接受的容器 `alwaystransparent` 参数。
- 私营民工改为名称、数量上下两行；消费品和卢布保留两位小数；供需数值禁止省略号并按 M/B 切换单位；贸易展开按钮左移到右侧方格中心；卢布内联图标补 `legacy_lazy_load=no`。
