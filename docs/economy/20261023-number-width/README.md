# 经济数值完整显示检查

本轮针对统一 K/M/B/T/Qa/Qi 等单位后的国库、每周收支、消费品供需及相关数值，检查省略号和实际字宽。

最终只修改 `tools/economy/build_ui.py` 和生成的 `interface/APDC_economy_panel.gui`：14 个数值文本框明确设置 `truncate = no`；供给、需求的数值框从 58px 加宽到 64px，并分别调整到 x=572、635，保持现有字体和纵向位置。其余数值框的原有宽度足够，保留原尺寸。新增 `tools/economy/number_layout_qa.py` 为只读的字库宽度检查工具。

检查覆盖国库、每周收支、总消费品、供给、需求、额外输入/输出、消费品净贸易、贸易伙伴数量、采购总价、分配率及三项民生每周变化。

## 字体与界面检查

- 按游戏实际 BMFont 的字形前进宽度、字距、偏移和描边边界计算，分别覆盖中文覆盖字库和原生数字字库，合计 6,248 组字宽/字高检查通过。
- 覆盖全部单位后缀、两位小数、正负号、中文标题及实际 15×20 的卢布图标。国库 258px 框的最宽测试行占 161px，每周变化 310px 框的最宽测试行占 198px。
- 供给、需求的最长正数含描边约 60px，64px 数值框能容纳；两列同时显示最宽内容时，所有测试后缀和数字组合的最小间隔为 2.5px。
- 结果见 `font-fit-verification.json`。这属于字库和界面配置检查，没有进行实际截图或鼠标视觉验收。

## 引擎验证

实际 GER 2060 后台开局通过原有 60 项面板/经济保护检查、13 项直接来源检查、39 项单位检查，共 112 项。后者含 9 项接近单位边界的专项检查。

引擎的 `|2` 原生显示实测为截取两位小数：999.995 显示 999.99，不会因四舍五入变为四位的 1000.00。最终单位格式器和全部经济计算、结算、贸易、美术、本地化、法案、GUI 回调均与本轮备份逐字节相同，没有增加显示进位算法。早期进位假设的诊断记录保留在 `runtime/carry-diagnostic`，最终版本证据位于 `runtime/final`。
